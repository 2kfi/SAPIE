# antislop audit 001, 2026-11-20

Mode: AFTER (session override, chosen by the user).
Scope: launcher (`client/src-tauri/src/main.rs`) and web UI (`web/`). Server code is out of scope for
this audit.
Nothing has been changed. Pick the numbers you want fixed and I will fix only those, then write a
follow-up report.

Priority mapping: Hard Gate findings are HIGH, Purpose-Gate findings are MEDIUM, Quality Lock
findings are LOW.

## Findings

1. **HIGH, R-26 (dead control).** The launcher's primary action says "Save connection details" or
   "Use details for this session", then marks the Connect step done and advances. `connect()` only
   validates the `host:port` shape and writes JSON. It never opens a connection or calls
   `/api/v1/login`, so the user is told they connected when they did not. Reason: a control that
   claims a network result without doing the network work is a dead control.
2. **HIGH, R-24 (nav to nowhere).** The web rail has a "Games" item. Its screen is an empty state
   whose only content is "Game setup is handled by the native launcher." No game list, no action, no
   data. Reason: the nav promises a destination that does not exist.
3. **HIGH, R-37 (no direction for the launcher).** `web/DESIGN.md` covers the web SPA only. The
   launcher has no `DESIGN.md`, no recorded dials, and copies colour constants by hand in
   `main.rs`. Reason: direction is required before UI work, and the launcher currently has none.
4. **HIGH, R-27 (no loading state).** `detect_game`, `copy_dll` and `unpack_steamstub` read the
   executable and copy files synchronously inside the egui update loop. There is no pending state,
   progress or cancel, so the window can look frozen on a large game. Reason: a UI that displays
   data must have loading and error states.
5. **MEDIUM, R-06 (font depends on the machine).** The launcher reads Manrope and IBM Plex Mono
   from system fonts via `fc-match` and silently falls back when absent. The intended identity is
   therefore not guaranteed, and the reason for the fallback is not recorded. Reason: typography
   must be chosen for the product, not left to whatever the host has installed.
6. **LOW, R-05 (linear template).** The launcher is a fixed six-step wizard: Connect, Select, Detect,
   Install, Configure, Launch. Every user walks the same sequence, and a returning user still
   re-enters the flow to launch. Reason: composition should follow the content need, and the
   content need is a game library, not a setup checklist.
7. **LOW, R-20 (no launcher identity).** Inputs, grids, checkbox, scroll area and selectable labels
   are stock egui widgets with a recoloured palette. Replace the "SAPIE Launcher" title and it reads
   as any egui sample. Reason: identity must survive a logo swap.
8. **LOW, R-21 / R-34 (dark only, reason unrecorded).** The launcher hardcodes `Visuals::dark()`.
   The web UI is dark only and `web/DESIGN.md` states that fact without justifying it. Reason: a
   fixed theme needs a stated product reason, otherwise a working toggle is expected.
9. **LOW, R-31 (reasons not written).** Colour, spacing and radius choices for the launcher exist
   only as constants in `main.rs`. No one-line reason is recorded for the launcher surface, even
   where the web file records one. Reason: every major decision needs a written reason.

## PASS with evidence

- **R-02:** no em dash in launcher or web copy. Checked the string literals and JSX text.
- **R-17 / R-18 / R-36:** no invented statistics, testimonials, avatars or trust claims. The web
  and launcher show only API values or explicit empty states.
- **R-23:** the "S" mark and the "SAPIE" wordmark are the allowed text placeholder, not an invented
  logo asset.
- **R-25:** documented measured contrast in `web/DESIGN.md` clears AA (13.5:1 text, 8.69:1 muted,
  9.11:1 ink on ember). Launcher pairs are high contrast on dark surfaces.
- **R-29:** core palette is neutral plus one ember accent plus one status green.
- **R-32:** web focus ring is a 2px ember outline at 2px offset, targets are 44px, modals are not
  used for destructive flows. Launcher enables `accesskit`.
- **R-19:** one GSAP timeline on first shell mount, skipped under `prefers-reduced-motion`.
