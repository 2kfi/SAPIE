# 0.4 morning gate: real MW2 2009 run (M13-b)

This is a runbook for the Windows machine with the game installed. It was not executed in the
headless evidence run. The headless evidence is in `0.4-two-client.md`.

Do not edit application source to make this pass. If the DLL crashes, stop and save the logs. The
bug report is part of the evidence, not something to work around in a game folder.

## What this proves

- The Windows x86 legacy `steam_api.dll` boots real MW2 2009.
- The game signs in to a real `sapie-server` with appid `10190`.
- The SteamID and persona seen in the game match a row in SQLite.
- One in-game achievement and one stat reach the server and persist with appid `10190`.

## What this does not prove

- M13-c direct UDP and relay path selection. That needs two networks and is a separate run.
- Launcher click-through. This gate may use a manual DLL copy.
- Cross-compiled execution on any target other than the Windows machine used here.

## Before you start

Use a throwaway game account. Never put the account password in a screenshot, transcript, log or
commit.

Record the build once, at the top of the evidence file:

```powershell
git rev-parse HEAD
certutil -hashfile sapie-server.exe SHA256
certutil -hashfile steam_api.dll SHA256
```

Use this DLL:

- From a release archive: `steam_api/windows-x86-legacy/steam_api.dll`
- From this worktree build: `out/client/windows-x86-legacy/steam_api.dll`

Use the legacy build because MW2 2009 is the legacy x86 test game. Do not substitute the modern or
x64 library.

Start the server with no flags, from the directory that contains `web/dist`:

```bat
cd <archive-root>
sapie-server.exe > <evidence-dir>\server.log 2>&1
```

Expected first log line:

```text
sapie game protocol on :47584, admin API on 127.0.0.1:8080, web UI on 0.0.0.0:8081
```

If the accounts do not exist yet, create them through the web UI on `http://127.0.0.1:8081` with a
temporary `--allow-register` run, then stop the server and restart it with no flags. Do not leave
registration enabled for the gate.

## Game folder checklist

Work next to `iw4mp.exe`. Replace `<game-dir>` with the real path.

- [ ] Original `steam_api.dll` copied to `steam_api.dll.sapie-original`. Do not overwrite that
      backup on a later run.
- [ ] SAPIE DLL copied to `<game-dir>\steam_api.dll`.
- [ ] `<game-dir>\steam_appid.txt` contains only `10190`.
- [ ] `<game-dir>\sapie_server.txt` contains only `127.0.0.1:47584`, or the LAN address of the
      server plus `:47584`.
- [ ] If the original DLL is older than May 2016, `<game-dir>\steam_interfaces.txt` was generated
      from that original DLL. Otherwise record why it was not needed.
- [ ] Environment variables for the game process:

```bat
set SAPIE_USERNAME=<throwaway-username>
set SAPIE_PASSWORD=<throwaway-password>
start "" "<game-dir>\iw4mp.exe"
```

To generate `steam_interfaces.txt` from the original DLL:

```bat
mkdir "%TEMP%\sapie-interfaces"
cd /d "%TEMP%\sapie-interfaces"
powershell -ExecutionPolicy Bypass -File <repo>\client\scripts\find_interfaces.ps1 <game-dir>\steam_api.dll.sapie-original
copy steam_interfaces.txt <game-dir>\steam_interfaces.txt
```

## Run checklist

- [ ] Server started with no flags and `server.log` captured.
- [ ] Game started with the two environment variables set.
- [ ] Game reached the multiplayer menu or lobby with the expected persona. Capture a screenshot as
      `<evidence-dir>\persona.png`.
- [ ] In-game SteamID or player card matches the server row. If the game does not print the numeric
      ID, capture the persona and compare it with SQLite plus the server log. Record the limitation.
- [ ] Unlock one real MW2 achievement. Capture the toast or stats screen as
      `<evidence-dir>\achievement.png`.
- [ ] Change one stat through normal gameplay. Record the stat name from
      `<game-dir>\steam_settings\stats.json` if that file exists, or from the SQLite row after the
      run. Do not invent a name.
- [ ] Game closed cleanly if possible. Server stopped with Ctrl+C.

## SQLite readback

Run after the game has flushed stats, with the server stopped:

```sh
sqlite3 <archive-root>\sapie.db "SELECT steam_id, username, persona_name FROM accounts WHERE username='<throwaway-username>';"
sqlite3 <archive-root>\sapie.db "SELECT steam_id, appid, persona_name, lobby_id, updated_at FROM presence WHERE appid=10190;"
sqlite3 <archive-root>\sapie.db "SELECT steam_id, appid, name, achieved, unlock_time FROM achievements WHERE appid=10190 AND steam_id=<STEAM_ID>;"
sqlite3 <archive-root>\sapie.db "SELECT steam_id, appid, name, hex(value), updated_at FROM stats WHERE appid=10190 AND steam_id=<STEAM_ID>;"
```

Save the output as `<evidence-dir>\sqlite-readback.txt`. Redact any password if a shell transcript
captured one.

## Evidence to attach

- `build.txt`: git SHA, server SHA256, DLL SHA256, DLL variant and chosen era.
- `server.log`: full zero-flag server log.
- `command-transcript.txt`: commands and their output, with credentials redacted.
- `persona.png`: in-game persona or player card.
- `achievement.png`: in-game achievement or stats screen.
- `sqlite-readback.txt`: the four queries above.
- `game-folder.txt`: file names present next to `iw4mp.exe` and whether `steam_interfaces.txt` was
  used.
- If a crash happens: Windows event entry, any `steam_api` error log, and the exact repro steps.

## Pass criteria

Mark M13-b PASS only if every line below is true:

- [ ] Server log contains the zero-flag startup line.
- [ ] Game boots with `windows-x86-legacy/steam_api.dll` and appid `10190`.
- [ ] In-game persona matches the `persona_name` in SQLite and the server log shows the account
      connecting.
- [ ] Presence row has `appid=10190`, which proves the game did not fall back to Goldberg LAN mode.
- [ ] One achievement row has `achieved=1` and `unlock_time > 0`.
- [ ] One stat row has `appid=10190` and a non-empty `hex(value)`.
- [ ] No DLL crash, no silent fallback, no password in any evidence file.
- [ ] Original DLL backup is still present.

## FAIL and STOP conditions

Stop the gate and report rather than patching application source if any of these happen:

- The DLL crashes or the game exits before the persona check.
- The presence row is missing or has the wrong appid.
- The game assigns a local SteamID that does not match the server row.
- Achievements or stats do not reach SQLite after a normal in-game unlock or stat change.
- The original DLL backup is missing or was overwritten.

Paste the failure logs into the report and keep the game folder unchanged. A failed gate with clean
evidence is useful. A patched game folder is not.
