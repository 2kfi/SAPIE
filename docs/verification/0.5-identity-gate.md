# 0.5 identity gate, M22-e evidence

Status: evidence prepared for user and chief review. G1 is not passed by this record. The owner of
G1 is the user plus the chief, per `plan.md` 13.8.

## What this prototype is

A clickable Qt Quick prototype under `launcher/ui/prototype/`. It uses the real `AppShell`,
`Sidebar`, `Toolbar` and gallery primitives, the `Tokens` singleton and no webview, HTML, remote URL
or external script. Five screens are wired through the sidebar: Sign in, Library, Game, Friends and
Settings. Game is exposed in the prototype rail so it can be reviewed directly. In production it is
reached from a library tile, not from the rail.

A toolbar Select switches every screen between `empty`, `loading`, `error` and `data`. Each state has
a specific message and a real action. Retry moves through loading to data. The example address action
fills the sign in field and reports that no connection was made. Add game and Add friend open a
dialog that states the prototype boundary. Sign in validates all three fields before navigating.
Play and friend row actions report that no process or account is connected. No game, player, cover,
stat or testimonial is invented. Every record is labelled as a placeholder, and no repo fixture with
a real local game record was found.

Violet is limited to the selected sidebar row, focus rings, primary actions and the existing monogram
primitive's token fill. Status is a dot plus a text label. Surfaces are flat token colours with no
glass, gradient or glow.

## Mark direction used

The prototype uses `design/icons/mark-directions/candidate-a-nested.svg`, the solid violet field with
a dark keyhole and a nested triangle. `design/icons/README.md` recommends it because the triangle
and the field share one colour, so it holds at 16px. The prototype also shows `design/wordmark.svg`
and the candidate A export in Settings. All are labelled provisional and pending G1. No final art was
generated for this stage.

## Decisions still owed by the user at G1

1. Mark pick. Candidate A nested, B outline or C inverted. The prototype uses A as a stand-in, not a
   decision.
2. ExtraBold wording. `design/identity.md` says Manrope ExtraBold, while the type system caps weight
   at 700 and the SVG wordmark uses 700. Pick the wording or the weight.
3. Monogram motif. `MonogramTile` is the current deterministic appid tile. Accept it as the recurring
   game tile motif or replace it.
4. `--text-muted` AA choice. The measured pairs fail normal text. Choose to restrict the token to
   large text, raise it to a value such as `#8E95A0`, or keep it and record the exception. The
   prototype uses `textSecondary` for new small text. The existing `SidebarGroup` primitive still
   uses `textMuted` for its 12px group label, so that pair is part of the same decision.

## What was NOT verified

- G1 is not signed off. The mark, ExtraBold wording, monogram motif and muted AA choice are still
  owed by the user.
- No rendered contrast audit. The figures above are token calculations from `design/DESIGN.md`, not
  samples of a captured surface.
- The swap-the-logo test and the GOG clone check need human review. This record does not certify
  them.
- AT-SPI with Orca, Windows UI Automation and screen-reader announcement of `Accessible` names were
  not exercised.
- The 860x560 minimum window and narrow layouts were not exercised. Captures are 1280x800.
- Manrope and IBM Plex Mono are not installed on this machine. The token names are used, but local
  rendering falls back to system faces. Bundling the TTF files is later work.
- Captured PNG files were produced and checked as valid 1280x800 images, but this agent could not
  visually inspect their pixels. Visual sign-off is owed by the reviewer.
- OS reduced-motion detection is platform work for M24 and M25. Only the in-app fallback toggle and
  its signal were tested.
- No real server, login, token storage, keychain, file picker, library write, install, restore or game
  launch was exercised. These are prototype boundaries, not production behavior.
